# Adoption-readiness fixes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop nested git worktrees from poisoning the whole-graph analyzers, and close four smaller adoption gaps found in a greenfield audit.

**Architecture:** The worktree fix lands in three independent layers — a shipped `.gitignore`/depcruise default, an unconditional runtime filter in `verify` that drops violations resolving inside a nested worktree, and an adoption-time question in the `adopting-guardrails` skill. The remaining work is four small, unrelated changes: richer analyzer-failure stderr, an eslint-enabled leg in the tarball smoke test, a printed pointer to the adoption guidance, and documentation accuracy.

**Tech Stack:** TypeScript (strict), Vitest, tsup → `dist/*.mjs`, ESLint 9 flat config, knip, dependency-cruiser, Stryker.

**Spec:** `docs/superpowers/specs/2026-09-03-adoption-readiness-fixes-design.md`

## Global Constraints

- **TDD, always.** No production code without a failing test first. This is non-negotiable in this repo.
- **Never weaken a rule to pass.** No `eslint-disable`, `@ts-ignore`, `as any`, `.skip`, deleted assertions, or raised thresholds. The diff-auditor rejects these and will block the commit.
- **`guardrails-plugin/` is the ONLY source of truth for skills and agents.** `.claude/agents/`, `.claude/skills/`, `docs/guardrails/`, `guardrails-core/guidance/`, `guardrails-core/templates/`, and `.github/agents/` are all generated by `npm run build`. Never hand-edit them. `guidance/`, `templates/`, and `.github/agents/` are **committed** — regenerate and commit them in the same commit as the source change.
- **Violation `file` paths are repo-relative POSIX strings.** Worktree paths from git are absolute. Convert once, at the boundary.
- **Commit in small, logical steps.** One task, one commit.
- **Node >= 24.** ESM only, `.js` extensions on relative imports.
- **This session is worktree-isolated.** Run every command from the worktree root; use plain, separate git commands (compound git invocations are refused).

```ts
const WORKTREE_PREFIX = 'worktree ';

/**
 * Repo-relative POSIX prefixes for every git worktree checked out INSIDE
 * `repoRoot`.
 *
 * A nested worktree is untracked but NOT ignored, so whole-graph analyzers
 * (knip, dependency-cruiser) walk into it and report a second checkout of the
 * repository as if it were part of this one. Claude Code creates worktrees
 * under `.claude/worktrees/` by default, so the recommended workflow produces
 * this state; measured here, it was 559 phantom violations and a commit gate
 * that refused every commit.
 *
 * Parsing is separated from running git so the record-shape rules — the first
 * record is always the main checkout, `HEAD`/`branch`/`locked` lines are noise
 * — are provable without a repository.
 */
export function parseNestedWorktrees(
  stdout: string,
  repoRoot: string,
): string[] {
  const nested: string[] = [];
  for (const line of stdout.split('\n')) {
    if (!line.startsWith(WORKTREE_PREFIX)) {
      continue;
    }
    const absolute = line.slice(WORKTREE_PREFIX.length).trim();
    if (absolute.length === 0) {
      continue;
    }
    const relative = path.relative(repoRoot, absolute);
    // '' is the main checkout itself — an empty prefix would match every file
    // in the repository and filter the entire run away.
    if (relative.length === 0) {
      continue;
    }
    // Compare against the parent-traversal SEGMENT, not the two characters: a
    // directory legitimately named '..cache' is a child, not an escape.
    if (relative === '..' || relative.startsWith(`..${path.sep}`)) {
      continue;
    }
    if (path.isAbsolute(relative)) {
      continue;
    }
    nested.push(relative.replaceAll('\\', '/'));
  }
  return nested;
}

/**
 * Is this repo-relative file inside one of `prefixes`?
 *
 * The `/` in the second test is load-bearing: without it, a worktree named
 * `feature` would also swallow a sibling directory named `feature-old`.
 */
export function isInsideNestedWorktree(
  file: string,
  prefixes: readonly string[],
): boolean {
  return prefixes.some(
    (prefix) => file === prefix || file.startsWith(`${prefix}/`),
  );
}

/**
 * Nested worktrees for `repoRoot`, or none if git cannot answer.
 *
 * Degrading to `[]` is the STRICT choice here, not a fail-open: this list only
 * ever removes violations, so filtering nothing leaves the gate exactly as
 * strict as it is today. A genuinely missing git is already reported by
 * `changedTypeScriptFiles`, so this must not report it a second time.
 */
export async function nestedWorktreePaths(
  exec: Exec,
  repoRoot: string,
): Promise<string[]> {
  const result = await exec('git', ['worktree', 'list', '--porcelain'], {
    cwd: repoRoot,
  });
  if (result.spawnFailed === true || result.code !== 0) {
    return [];
  }
  return parseNestedWorktrees(result.stdout, repoRoot);
}
```

**Where this goes and why.** `runVerify` ends by wrapping the accumulated `violations` in `withPackages(...)`. The filter goes immediately before that call, so it applies uniformly to **every** analyzer rather than being duplicated into each adapter — and so it also covers any analyzer added later.

Use `options.exec`, **not** the `tracked` exec. `trackSpawnFailures` records spawn failures and the caller turns them into a `guardrails/analyzer-missing` violation for git; routing this call through it would double-report a missing git that `changedTypeScriptFiles` already reported.

describe('nested worktree filtering', () => {
  // knip is whole-graph and walks into a nested worktree, reporting a second
  // checkout of this repo as dead code in THIS one.
  const knipReport = JSON.stringify({
    issues: [
      { file: '.claude/worktrees/wt/src/dead.ts', files: true },
      { file: 'src/really-dead.ts', files: true },
    ],
  });

  function execFor(worktreeStdout: string): Exec {
    return (command, args) => {
      if (command === 'git' && args[0] === 'worktree') {
        return Promise.resolve({
          stdout: worktreeStdout,
          stderr: '',
          code: 0,
        });
      }
      if (command === 'knip') {
        return Promise.resolve({ stdout: knipReport, stderr: '', code: 1 });
      }
      // Every other git call (diff/ls-files/rev-parse) reports one changed file.
      return Promise.resolve({ stdout: 'src/a.ts\n', stderr: '', code: 0 });
    };
  }

  it('drops violations inside a nested worktree and keeps the rest', async () => {
    const { violations } = await runVerify({
      repoRoot: '/repo',
      baseBranch: 'main',
      exec: execFor('worktree /repo\n\nworktree /repo/.claude/worktrees/wt\n'),
      profile: 'commit',
      analyzers: { knip: 'required', eslint: false, tsc: false },
    });
    expect(violations.map((violation) => violation.file)).toEqual([
      'src/really-dead.ts',
    ]);
  });

  it('keeps every violation when there is no nested worktree', async () => {
    const { violations } = await runVerify({
      repoRoot: '/repo',
      baseBranch: 'main',
      exec: execFor('worktree /repo\n'),
      profile: 'commit',
      analyzers: { knip: 'required', eslint: false, tsc: false },
    });
    expect(violations.map((violation) => violation.file)).toEqual([
      '.claude/worktrees/wt/src/dead.ts',
      'src/really-dead.ts',
    ]);
  });
});

**Files:**

**The failure this fixes.** A greenfield repo with no `eslint.config.js` produces exactly this stderr, and the current code keeps only line 1:

```
Oops! Something went wrong! :(

ESLint: 9.39.5

A config object is using the "env" key, which is not supported in flat config.
```

The agent is handed `Oops!` and nothing else. Five meaningful lines reaches the diagnosis with headroom; 500 characters stops a stack trace from flooding the manifest. The decorative banner is deliberately **kept rather than pattern-matched away** — recognising each tool's banner is hardcoded third-party knowledge of exactly the kind this repo's guidance warns rots silently.

```ts
/** How much of a failed tool's stderr reaches the violation message. Five
 *  meaningful lines clears the deepest real case measured — eslint puts its
 *  diagnosis on line 3, behind a banner and a version — without letting a
 *  stack trace become the whole manifest. */
const STDERR_DETAIL_LINES = 5;
const STDERR_DETAIL_CHARS = 500;

/**
 * The useful head of a tool's stderr, for a violation message that names *why*
 * the tool failed rather than just that it did. `undefined` when stderr carried
 * nothing.
 *
 * Blank lines are dropped but decorative banners are kept: eslint's first line
 * is `Oops! Something went wrong! :(`, and teaching this function to recognise
 * that would be hardcoded knowledge of a third-party tool's copy — the class of
 * coupling that rots silently on upgrade. Keeping five lines gets past every
 * banner without needing to know any of them.
 */
function stderrDetail(text: string): string | undefined {
  const lines = text
    .split('\n')
    .map((line) => line.trim())
    .filter((line) => line.length > 0)
    .slice(0, STDERR_DETAIL_LINES);
  if (lines.length === 0) {
    return undefined;
  }
  const joined = lines.join('; ');
  return joined.length <= STDERR_DETAIL_CHARS
    ? joined
    : `${joined.slice(0, STDERR_DETAIL_CHARS)}…`;
}
```

```ts
const detail = stderrDetail(stderr);
const suffix = detail === undefined ? '' : ` stderr: "${detail}"`;
```

and change the message's trailing `detail` to `suffix`. Update the function's doc comment: "…and — when present — the head of stderr".
