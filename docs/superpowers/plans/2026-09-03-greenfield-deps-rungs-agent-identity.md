# Greenfield deps, cadence rungs, and agent identity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an agent build a greenfield TypeScript project under the loop — install a coherent stack, commit without a growing mutation tax, and fan out subagents while a fixer runs.

**Architecture:** Three independent changes. (A) A generic peer-range check computed by `npm ls`, plus prescriptive dependency guidance in the adoption skill. (B) A third local cadence rung: pre-commit narrows to staged files, a new pre-push runs the branch diff. (C) The fixer scope-lock keys on agent identity where the host supplies it, falling back to today's session scope where it does not.

**Tech Stack:** TypeScript (strict), Vitest, tsup → `dist/*.mjs`, ESLint 9 flat config, knip, dependency-cruiser, Stryker.

**Spec:** `docs/superpowers/specs/2026-09-03-greenfield-deps-rungs-agent-identity-design.md`

## Global Constraints

- **TDD, always.** No production code without a failing test first.
- **Never weaken a rule to pass.** No `eslint-disable`, `@ts-ignore`, `as any`, `.skip`, deleted assertions, raised thresholds. The diff-auditor rejects them.
- **guardrails-core has ZERO runtime dependencies.** Do not add `semver` or any other package to make this easier. `npm ls --json` is the range engine.
- **No hardcoded third-party version tables.** The spec rejects that approach explicitly; ask the package manager instead.
- **`guardrails-plugin/` is the only source of truth for skills/agents.** `.claude/`, `docs/guardrails/`, `guardrails-core/guidance/`, `guardrails-core/templates/`, `.github/agents/` are generated by `npm run build`; `guidance/`, `templates/`, `.github/agents/` are committed — regenerate and commit them with the source change.
- **Do not trust an exit code alone.** `npm ls` exits 0 on a broken graph; parse its `problems`/`invalid` fields.
- **Define test helpers at module scope**, not inside `describe` — `unicorn/consistent-function-scoping` has blocked this branch three times.
- **Verify commits with `git log`,** never a piped exit code.
- **Commits are slow** (branch-scoped mutation testing — the thing Task B fixes). Run them with `run_in_background` and confirm with `git log`.

### Task A1: Report peer-range violations from `npm ls`

**Files:**

- Create: `guardrails-core/src/verify/npm-peers-adapter.ts`
- Test: `guardrails-core/test/verify/npm-peers-adapter.test.ts`

**Interfaces:**

- Consumes: `Violation` from `../violation.js`.
- Produces: `parseNpmLsJson(stdout: string): Violation[]`

**Background.** `npm ls --json --all` emits a nested tree. Any package installed at a version violating a peer range carries an `invalid` string naming the ranges and who required them, plus a `problems` array. The same problem repeats once per path through the tree — one real fixture produced the same `typescript@7.0.2` finding a dozen times.

Real shape, trimmed:

```json
{
  "dependencies": {
    "typescript-eslint": {
      "version": "8.69.0",
      "dependencies": {
        "typescript": {
          "version": "7.0.2",
          "invalid": "\">=4.8.4 <6.1.0\" from node_modules/typescript-eslint, \">=4.8.4 <6.1.0\" from node_modules/@typescript-eslint/parser",
          "problems": [
            "invalid: typescript@7.0.2 /path/node_modules/typescript"
          ]
        }
      }
    }
  }
}
```

`missing` entries are deliberately NOT reported — an absent optional peer is normal, while `invalid` means a package IS present at a bad version.

- [ ] **Step 3: Implement**

```ts
/**
 * npm peer-range adapter: maps `npm ls --json --all` into `Violation[]`.
 *
 * npm already knows every package's peer ranges and which installed versions
 * violate them, so this asks npm rather than carrying a table of supported
 * analyzer versions. That is deliberate: a hardcoded version table is the
 * "hardcoded third-party knowledge rots silently" failure this repo's guidance
 * warns about, and it would need editing every time the ecosystem moved.
 *
 * Why this exists when npm validates peers at INSTALL time: that check is
 * bypassed by `--legacy-peer-deps` and `--force` -- exactly what a stuck agent
 * reaches for -- and by monorepo hoisting. Those leave a graph that installs
 * cleanly and misbehaves later. This is the greenfield case: `npm i -D
 * typescript` installs a major no released typescript-eslint accepts.
 */
import type { Violation } from '../violation.js';

interface NpmLsNode {
  version?: unknown;
  invalid?: unknown;
  dependencies?: unknown;
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

function peerViolation(
  name: string,
  version: string,
  ranges: string,
): Violation {
  return {
    ruleId: 'guardrails/peer-range-violation',
    file: 'package.json',
    message:
      `${name}@${version} violates a peer range required by another ` +
      `installed package: ${ranges}. Pin ${name} to a version inside that ` +
      `range, or upgrade the package that requires it. npm reports this only ` +
      `when the graph was installed past its own peer check ` +
      `(--legacy-peer-deps, --force) or hoisted in a workspace.`,
    severity: 'error',
    fixable: false,
    tool: 'npm',
  };
}

/**
 * Walks the tree collecting `invalid` nodes, keyed by package name so the same
 * violation reached by several paths is reported once. `missing` is ignored:
 * an absent optional peer is normal, while `invalid` means the package IS
 * installed at a version that violates a range.
 */
export function parseNpmLsJson(stdout: string): Violation[] {
  let parsed: unknown;
  try {
    parsed = JSON.parse(stdout);
  } catch {
    return [];
  }
  if (!isRecord(parsed)) {
    return [];
  }
  const found = new Map<string, Violation>();
  const visit = (node: Record<string, unknown>): void => {
    const dependencies = (node as NpmLsNode).dependencies;
    if (!isRecord(dependencies)) {
      return;
    }
    for (const [name, child] of Object.entries(dependencies)) {
      if (!isRecord(child)) {
        continue;
      }
      const { invalid, version } = child as NpmLsNode;
      if (
        typeof invalid === 'string' &&
        invalid.length > 0 &&
        !found.has(name)
      ) {
        found.set(
          name,
          peerViolation(
            name,
            typeof version === 'string' ? version : 'unknown',
            invalid,
          ),
        );
      }
      visit(child);
    }
  };
  visit(parsed);
  return [...found.values()];
}
```

```ts
/**
 * npm's own peer-range verdict on the installed graph. Whole-graph and cheap,
 * so it sits at the commit rung with knip.
 *
 * No `withExitCodeCheck`: `npm ls` exits 0 on a graph it has just reported
 * problems for (measured), so the parsed output is the only signal. A spawn
 * failure yields no violations rather than an error — this is a diagnostic for
 * an incoherent install, and an environment without npm is not a broken repo.
 */
async function runNpmPeers(
  options: VerifyOptions,
  resolveBin: (tool: string) => string,
): Promise<Violation[]> {
  const result = await options.exec(
    resolveBin('npm'),
    ['ls', '--json', '--all'],
    {
      cwd: options.repoRoot,
    },
  );
  if (result.spawnFailed === true) {
    return [];
  }
  return parseNpmLsJson(result.stdout);
}
```

Compute the effective lock once, near `collectManifestScope`:

```ts
/** The fixer agent names, as the hosts report them. */
const FIXER_AGENT_TYPES: ReadonlySet<string> = new Set([
  'guardrail-fixer',
  'guardrail-fixer-thorough',
]);

/**
 * Is the caller the fixer?
 *
 * `undefined` agentType means the host does not report identity at all --
 * Codex, and Copilot's preToolUse -- so we cannot narrow and must keep the
 * session-scoped lock. Where identity IS reported, a non-fixer agent (the main
 * thread, or a sibling subagent fanned out in parallel) is left alone.
 */
function isFixerCaller(input: HookInput): boolean {
  return input.agentType === undefined
    ? true
    : FIXER_AGENT_TYPES.has(input.agentType);
}
```
